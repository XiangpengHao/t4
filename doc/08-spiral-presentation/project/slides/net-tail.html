INTERNAL · object_store, DIRECT FROM S3 · 1,024 GETS IN FLIGHT · doc/05

Reading from the network is extremely noisy. The same kind of request, sorted from fastest to slowest, spans an order of magnitude: with 1,024 GETs in flight straight from S3, median 451 ms, p99 3,686 ms, slowest 7,281 ms (doc/05-network.md). At 256 in flight it was 175, 407 and 861 ms. A query's GETs run in parallel and the query ends only after the slowest one finishes, so the max is what matters, not the median. A real case from run 6 on 26 Oct: one 23 s GET turned a 3.5 s query into a 26 s run. The left chart is a schematic, not data. You also wanted a chart of one request type's latencies sorted from lowest to highest: the per-GET CSV (store.gets.csv from run_queries) has what it needs.

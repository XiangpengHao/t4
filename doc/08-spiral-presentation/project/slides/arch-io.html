t4's architecture, in DataFusion's terms. DataFusion runs a query plan as partitions, and each partition is a tokio task. When a partition scans a file it calls t4 through object_store's get_range: an async function. Behind it, one I/O worker thread does every I/O in the process: it submits reads to io_uring and polls the completion queue, the same two rings as before. The callers can be on any runtime; t4 assumes no executor (src/io/io_worker.rs). Off Linux the same interface runs on a thread pool, and tests run on a simulated drive (src/io/mod.rs).

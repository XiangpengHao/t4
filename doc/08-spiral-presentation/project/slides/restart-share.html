The index lives in memory, so a restart would lose where every disk block is. A small log beside the first cache file keeps that (doc/13-persistence.md). Blocks go to disk in batches of 16 chunks; once a batch's writes are done, one append records them, together with the chunks freed since the last record. So the log costs one small write per 16 MiB written to disk, and nothing is ever synced. The rule that keeps it consistent: the log names a block only once its bytes are on the drive, and stops naming a chunk before that chunk is written again, so a replay can forget a block but never point at the wrong bytes. A killed process loses only the batch in flight and the blocks waiting for it, 32 MiB at most, fetched again. The disk tier lasts one boot: after a reboot t4 starts cold, which costs time and egress, never correctness. A build also claims the files it doesn't take back from their log, so a log of other files can't name their chunks.

On disk. foyer writes serialized entries into 16 MiB blocks: with its directory device each block is a file of its own; with its file device, blocks are offsets in one file or a raw device. Its devices open without O_DIRECT unless you set direct, so reads go through the page cache by default (io/device/fs.rs, file.rs). Its tiers are inclusive: the default policy writes an entry to disk when memory evicts it, and a disk hit is put back into memory while its disk copy stays (hybrid/cache.rs); with the page cache on, the bytes can sit in RAM twice. A disk read lands in a new buffer and is decoded into the value, a copy (serde.rs, foyer-common code.rs). Several devices are concatenated, the next used when one is full, and the combined device is marked a preview (io/device/combined.rs). t4: one preallocated cache file per drive, O_DIRECT, exclusive tiers, the SSD writing straight into the buffer the caller gets, chunks striped over the drives. Source: foyer 0.22.6, read from its code. Around the disk. foyer needs tokio: its spawner is a tokio runtime or handle, its flushers are tokio tasks, and its default I/O engine runs pread and pwrite on tokio's blocking pool (foyer-common spawn.rs, io/engine/psync.rs). Its io_uring engine is optional, threads of its own that callers reach through a channel. Its memory tier offers five eviction algorithms, FIFO, LRU, LFU, S3-FIFO and SIEVE, a closed set; its disk tier takes pluggable eviction pickers and admission and reinsertion filters, which see an entry's hash and size. Nothing in it locks its files or shares them between processes. If asked about restarts: foyer scans every block's index and rebuilds its own, so its disk tier survives one; t4 starts cold until its snapshot lands. t4 runs under any executor, owns one io_uring thread, takes any PlacementPolicy, and is getting a snapshot and shared mode (doc/10). Source: foyer 0.22.6, read from its code.

Microbenchmark, cold_reads in bench/: 128 GiB of 1 MiB blocks filled into each cache, then five passes of random reads in a new order, 128 in flight, with the page cache dropped before every pass. All caches on the same i7i.24xlarge, the same six SSDs as one RAID0, OS defaults. Every pass checks every byte: no wrong reads, no misses. Numbers are the median of passes 1 to 4; slowest is the worst read of any of them. CPU is the process's user plus kernel time over a pass, so Kismet's file system work counts: 83% of its CPU is in the kernel. The machine's busy time matches the process's on every row, so nothing hides in kernel threads or interrupts. t4 spends 0.055 CPU seconds per GB, 10x less than Kismet and 18x less than foyer as shipped; even reading the same blocks out of memory with pread costs 0.51, mostly the copy out of the page cache. foyer tuned (O_DIRECT, its io_uring engine) is the closest, at 0.20, mostly in user space. Throughput is a tie, so it isn't on the slide: fio on another i7i.24xlarge shows these SSDs sustain 25.6 GB/s, 4.27 a drive, plus a burst of about 25 GB after they rest, at any queue count or depth. Kismet and foyer as shipped measured about 31 GB/s a pass because dropping 128 GiB of page cache before each pass takes seconds and rests the drives: each of their passes read one burst above 25.6. t4 and foyer tuned have nothing to drop, so only their first pass bursts, and the rest read at 25.9. If asked: the harness, not the caches. Memory pressure, bottom row: foyer as shipped in a cgroup of 8 GiB falls to 11.4 GB/s at 7.3 CPU seconds per GB, slowest read 369 ms. Readahead pulls in pages the next random read doesn't want, the drives read 25% more than asked, and reclaim takes the CPU, in the process itself. Kismet under the same cap barely slows. t4's reads bypass the page cache, so it has nothing there to lose; we did not run it capped.

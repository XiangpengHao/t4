A query may ask for one long range. Part of it is in memory, part on disk, part only in S3. t4 splits the read by tier automatically: memory blocks are served from RAM, disk blocks become io_uring reads spread over the drives, and the remote run becomes GETs of at most 4 MiB (src/cache/policy/read.rs). All three run at once, and the caller gets one answer. The block numbers and tiers here are an example, not a trace.

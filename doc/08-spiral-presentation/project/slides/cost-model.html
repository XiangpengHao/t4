The cost model. How many bytes does a query read, how long does it run, so what bandwidth does it need from storage? If the SSDs give more than that, and we do nothing stupid, the query from disk should match the query from memory. Real numbers: query 23 reads 13.8 GiB off the drives. One SSD caps at about 2.7 GiB/s, so the model says 5.1 s; we measured 5.03 s. Twelve SSDs give 36 GiB/s, so the model says 0.4 s; we measured 2.40 s, because decoding is now the limit, not the disk (doc/04-multi-device.md, End to end). Over the warm pass DataFusion asks for 3 GiB/s on average, far under what twelve drives serve. Your outline's example used 15 GB, 1 s and 30 GB/s for the partitioned set: swap in the partitioned q23 numbers once measured. Latency, you may ask? We'll get to it. The high-level idea: queries bottlenecked by disk are bandwidth-bound, and if compute and I/O interleave well enough, the latency difference hides.

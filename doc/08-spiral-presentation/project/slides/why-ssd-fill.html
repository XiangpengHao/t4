Click: the bytes arrive. On the left, pread asks the kernel to copy from the page cache into Vortex's buffer, and a CPU core does that copy: it reads every byte from memory and writes it again, and spends that time not running the query. On the right, t4 hands the read to the SSD. Its controller writes the bytes into the buffer by DMA, straight from the drive, and no core touches them; the CPU only queues the read and picks up the completion. Those cores go back to decoding and running the query. While the SSDs can supply the bytes as fast as the query uses them, that saved copy is why t4 from SSD finishes first. The cost model in the evaluation makes this exact: time is about the larger of the query's own time and bytes divided by the SSDs' bandwidth.
